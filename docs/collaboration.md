# 协作使用指南

状态：本文描述 0.5.5 的协作能力。0.5.4 不包含这些新增功能；升级客户端还需要兼容的 Chatroom 服务端。英文执行协议见 [Collaboration execution results](collaboration-execution.md)。

## 从聊天到协作

协作沿用群成员与群管理权限，不需要另建一套成员。Web UI 在同一个工作区提供聊天、任务、看板、资产、成员与设置。群公告仍面向公告的原有读者，协作约定是成员可见的执行上下文，两者不要混用。

Chatroom 保留以人的聊天为中心的入口，在会话中打开协作面板。它与本地 Web UI 共享协作数据，但不是同一种页面布局。

| 概念 | 用途 | 与其他内容的关系 |
| --- | --- | --- |
| 聊天 | 沟通、补充上下文 | 可以形成任务；聊天消息本身不等于执行指令 |
| 任务 | 一个有目标、负责人、讨论和验收结果的工作事项 | 可明确派单给 Agent，并积累执行记录与资产 |
| 看板 | 人工协调待办、进行中、已完成事项 | 用于安排与跟踪；移动卡片不是启动 Agent 的命令 |
| 执行记录 | 某个 Agent 接受一次明确派单后的处理结果 | 同一任务可以有多次执行；执行成功不自动代表业务验收完成 |
| 资产 | 协作中共享的输入与成果文件 | 存在客户云空间，可关联任务，由成员下载使用 |

## 完成一次协作

1. 管理员在“资产”中配置云空间，验证并保存。当前 Agent 派单需要先配置存储，即使计划执行的是纯文本工作。
2. 建立任务，说明目标和验收标准，选择负责人。需要输入文件时先上传到资产。
3. 在任务中选择执行 Agent，填写这一次的具体工作指令，再明确派单。负责人和执行 Agent 是不同职责，负责人不一定是 Agent。
4. Agent 所在的 Lite 必须在线，Provider 必须可用，且已有权限允许完成工作。成员资格不授予额外的本机文件、命令或网络权限；生成文件需要相应 Provider 能力。
5. 执行端获取任务上下文和输入资产，在独立工作目录处理，核对结果回执与输出文件，上传后报告执行结果。
6. 成员从云空间下载成果，必要时继续派单给其他 Agent。任务负责人检查业务结果后确认完成。

这套流程没有引入单独的专家或 Skill 管理页面，也不代表系统会自动规划、分工或调度所有 Agent。当前执行输入包含有界的讨论、历史结果和资产，并非全部无限历史。

## 云空间配置

管理员从“资产 → 配置云空间”选择厂商。选项由服务端提供；只升级 Lite 而不升级服务端，不会凭空增加支持的厂商。

| 厂商 | 配置字段 | 自动生成的服务地址 |
| --- | --- | --- |
| 七牛云 | Bucket、区域、AccessKey、SecretKey | `https://s3.<region>.qiniucs.com` |
| 腾讯云 COS | 完整 Bucket 名称（含 APPID）、区域、SecretId、SecretKey | `https://cos.<region>.myqcloud.com` |
| Amazon S3 | Bucket、区域、Access Key ID、Secret Access Key | `https://s3.<region>.amazonaws.com`；中国区域加 `.cn` |
| Cloudflare R2 | Bucket、32 位 Account ID、S3 API Access Key ID、Secret Access Key | `https://<account>.r2.cloudflarestorage.com`；区域固定 `auto` |

使用表单列出的区域。不接受任意自定义 Endpoint；R2 特殊 jurisdiction 地址、临时会话令牌、自建 S3 服务以及其他网盘不在当前配置范围内。R2 要填 S3 API 凭据，不是 Cloudflare 通用 API Token。

凭据由 Chatroom 服务端加密保存，成员通过短期签名 URL 访问，不需要管理员为每次成员变化分发永久密钥。协作成员共享资产访问权限。退出协作不会删除其已下载的文件，也不会立即撤销已经签发的短期链接。

连接验证只检查连接和文件列举权限，不创建或删除文件，不能代替上传、下载和浏览器 CORS 验收。请实际上传并下载一个非敏感测试文件。七牛已有真实协作证据；COS、S3、R2 本次完成的是配置、签名及界面测试，真实账号验收仍待完成。

同一厂商和 R2 账号下，留空两个密钥字段可以保留原密钥。切换厂商或 R2 账号需重新填写密钥。已有资产时不能直接改变厂商、账号、桶或区域，以免旧资产失去位置引用；当前不提供资产迁移功能。

## 结果异常时

“结果待确认”不等于执行失败。超时、回执缺失、上传结果不确定或运行端重启后，先检查原执行记录、Provider 状态和已有资产，再做人工结果确认，不要直接重复派单。

运行中的 Lite 可以在超时后最多十分钟内接收原 Provider 的受限迟到回复，并关联原执行。已持久化的回执可在重启后恢复；进程退出前没有收到的回复无法凭空重建。业务内容是否正确仍需人工验收，详见[执行结果契约](collaboration-execution.md)。

客户云空间是共享资产存储，Lite 本地目录只是执行与恢复所需的工作副本。未知结果会保留文件，终态确认后清理，不承诺文件从未落地本机。群协作与资产不属于私聊 E2EE 的覆盖范围，参见[数据处理说明](../PRIVACY.md)。
