# OpenClaw 计划第三方对抗性审查与主审裁决

日期：2026-09-05。被审对象：本目录开发计划 v1；审查源码基线：`b43667d`。裁决已应用到[计划 v2](openclaw-version-compatibility-2026-09-05.md)。

审查方：本任务独立子 Agent `openclaw_plan_adversarial`。它与主审具有相同工作区读取权限，未指定不同模型；这里的“第三方”指独立审查角色，不代表外部机构认证。用户明确要求对抗性审查，审查方被要求不迎合主审，优先质疑事实与修改范围。

## 1. 方法与总体意见

第三方只读计划、当前源码和本机 OpenClaw 2026.9.2 安装包，并通过内存替身验证 CLI steer；没有修改产品文件、真实配置、启动生产 Gateway 或调用真实模型。主审另外在内存 SQLite 中复现摘要误冲突，并核对第三方引用的关键代码链。

第三方原结论：

> 计划的核心问题成立，但原计划把必要兼容修复与尚未证明必要的权限架构扩展捆绑过紧。应接受局部修复，缩减统一规划、binding 迁移及跨实例治理的首批范围。

主审接受这一总体判断。保留已证实缺陷的最小修复；将新增原生权限所需保护设为该控制上线前的条件门槛，不作为所有调用兼容修复的前置工程。

## 3. 复现记录与证据限制

### E1：主审摘要误冲突

使用当前 build 的 `snapshotFromProvider` 和 `ProviderSecurityPolicyService`，仅创建内存 SQLite。Provider 为稳定的可用替身，不访问真实运行配置。

步骤：第一次快照 → storeCapability → preflight；将测试时间增加 10ms → 第二次快照 → storeCapability → commit。

结果：

```json
{
  "sameFingerprint": true,
  "sameControls": true,
  "digestChanged": true,
  "commitResult": "PROVIDER_CAPABILITY_CONFLICT"
}
```

证明无语义变化的刷新可造成权限保存误冲突；不证明权限被放宽或绕过。实施时应转为仓库回归用例，并同时验证真正变更仍然被拒绝。

### E2：第三方 steer 失败误判

第三方使用当前 build，经 VM 注入假的 runCli/运行入口，从不 spawn 或连接模型：

- `code=1, stdout=''`：steer 返回 null，并记录 OK。
- `code=1, stdout={payloads:[{text:'failure output'}]}`：同样返回 null，并发出 agent.reply。

这是独立 Agent 的复现报告，主审核对了源码缺失退出检查，未在本轮再次运行同一 VM 复现。计划要求落地时加永久回归。

### E3：异步完成时序

本轮证据为源码调用链核对，不是连接真实 Gateway 的复现。能够证明发送后返回与安全 turn 标为 COMPLETED 的时序；尚不能据此声称生产发生了错误授权或外部副作用。A0/A3 需验证真实处理链上的 final、error、timeout 和重复事件。

### 历史与环境范围

前轮 91/91 是当时的相关回归结果，本轮没有重跑，也不是跨版本真机矩阵。2026.6.1、2026.7.1-2 本轮未安装或启动；2026.9.2 的上游源码与前轮状态锁复现不能替代旧版证明。未做真实模型、真实 IM 或生产服务验证。

## 4. 裁决后的范围控制

立即修复的计划只覆盖已确认观察缺口、误冲突、调用失败判定、锁处理、初始化和协议/终态局部问题。现有协议协商、会话结构与投递顺序优先保留。

以下不再无条件进入首批：完整规划层、所有配置/插件全面 fingerprint、第二套跨进程锁、Gateway CLI 新通道、agent exec 替换、binding 整体迁移、跨所有 Provider 的权限比较器与取消状态机。

这些限制不能被用来绕过原生权限的上线门槛：某控制确实依赖会话、共享配置、在途任务或降级保护，就必须在该控制上线前补足对应最小机制，或保持该控制不支持。

本轮只修改本计划和审查文档，不提交产品实现，也不部署。
