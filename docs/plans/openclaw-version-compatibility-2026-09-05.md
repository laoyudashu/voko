# OpenClaw 多版本兼容与访客权限开发计划 v2

日期：2026-09-05。状态：用户已批准实施；A 线实现及 B 线调查已落地，验证记录见 [交付矩阵](../providers/openclaw-compatibility.md)。下文保留批准时的问题与验收边界。

源码基线：`b43667d`。实施前核对 HEAD 和相关文件漂移。范围是 OpenClaw 多版本兼容与其访客权限接入，复用现有 Provider 框架；不重写所有 Provider，不包含生产 Gateway 安装、修改主人现有权限、发布或部署。

[第三方审查与逐项裁决](openclaw-version-compatibility-review-2026-09-05.md)

## 实施补充

A0～A4 已落实，B 线已交付控制证据清单，未满足独占配置/逐回合执行证明的原生权限保持不开放。

实施中另以回归测试确认并做了局部修复：

- 全局包目录软链接切换和命名 CLI 覆盖需要使解析结果更新，不能错选另一份全局安装。
- 排队期间隔离调用方超时，不能让过期任务在等待结束后启动；提交前复查当前回合，截止时间记录结果未知。
- 2026.9.2 的 `agents.entries` 与旧 `agents.list` 结构不同；实例枚举、注册和工作区读取统一做只读归一化，不新增配置迁移。

这些补充均保持既有 Provider、路由及数据库边界。实际验证结果和未覆盖项集中记录在 [交付矩阵](../providers/openclaw-compatibility.md)，以下为批准时的计划及审查依据。

## 1. v2 的主要调整

- 将交付拆成 **A：必做的最小兼容修复** 与 **B：有证据触发的原生权限接入**，不再要求原 P0～P5 整包串行完成。
- 保留现有 WS 功能协商；未知发行版本不等于不可调用，版本不作为唯一准入白名单。
- 不强制新增完整调用规划模块，先复用现有解析与调用代码，实际重复出现后再提取小型 helper。
- 稳定摘要误冲突、CLI steer 忽略失败和异步策略过早完成列为明确的最小修复；不把它们夸大为已证明的权限绕过。
- binding 数据库迁移、共享实例策略治理和完整权限变更状态机改为条件项。不能一概阻断旧会话，也不能在尚未满足保护条件时先开放新权限。
- 历史版本重新取得证据；三平台按风险覆盖，不用所有维度的笛卡尔乘积阻塞第一批交付。

## 2. 兼容承诺与证据边界

分别报告调用兼容、权限可控、Provider 执行终态、VOKO 实际投递，不能互相替代。程序可启动或 WS 已连接不等于模型回复、权限限制或 IM 投递已通过。

首批版本锚点：`2026.6.1`、`2026.7.1-2`、`2026.9.2`。前两者仅有历史线索，尚未取得本轮固定版本运行证据。当前确认的是本机 2026.9.2 的代码和部分隔离复现，不是完整端到端验收。

| 情况 | 调用处理 | 权限处理 |
| --- | --- | --- |
| 已验证版本与协议 | 使用已验证路径，保留旧规则 | 仅开放该实例/transport 上有证据的控制 |
| 未知发行版本，但现有协议、参数和会话契约能被确认 | 保留协议兼容路径，状态显示“协议兼容，版本未验收” | 不继承未证明仍有效的原生权限证据 |
| 已知版本，但认证、协议或实例不符 | 返回具体原因，不能凭版本号放行 | 不满足所需策略即阻止该路径 |
| 无法确认调用契约或指定权限 | 明确未支持/待验证，不猜测参数或自动扩权 | 不静默改宽松默认值；普通访客可按原规则等待 Pull |

CLI 的未知契约只能通过有界的只读识别或已验证兼容规则确认，不能把访客任务当试探调用；WS 可复用已认证协议/功能协商。只有命令存在或 `--help` 参数存在不足以认证权限。预发布版本不能仅按数字大小继承稳定版权限证据。

精确版本可在证据足够时扩大为有界兼容范围；端点通过不代表中间所有版本真机通过。不承诺所有历史/未来版本具备全部功能，也不因缺少版本白名单条目而删除已知协议兼容路径。

## 3. 已确认的问题与不应夸大的结论

| ID | 已确认事实 | 证据强度及范围 |
| --- | --- | --- |
| F1 | OpenClaw 能力采集没有得到版本、协议与有效运行指纹；当前只有 additionalPrompt | 当前源码、前轮实机采集及替身变更路径复现；属于升级检测缺口，不是已有原生权限绕过 |
| F2 | capabilityDigest 含 observedAt/expiresAt | 主审内存 SQLite 复现：相同指纹和控制只刷新时间，preflight 提交报 PROVIDER_CAPABILITY_CONFLICT；第三方核对源码 |
| F3 | 2026.9.2 agent --local 要求状态目录独占 | 包内执行/锁源码，前轮隔离目录上游所有权锁与真实 CLI 复现退出码 1；不能据此推断所有旧版相同 |
| F4 | Gateway setup 只补 Token，mode 缺失时当前 Gateway 可拒绝启动 | 初始化源码与当前上游启动检查；是有条件配置缺口，未证明此次升级才引入 |
| F5 | WS 使用本机签名时间，首个任意 res.ok 可被当认证成功 | 源码事实；当前官方客户端使用有效挑战时间。未证明正常本机认证必然失败，v2 和 /health 仍有效 |
| F6 | CLI steer 不检查非零退出码 | 第三方用当前 build 与无进程替身独立复现：code=1 仍记 OK，带 payload 时还 emit agent.reply |
| F7 | WS 发送后返回 receipt，dispatcher 将安全 turn 标 COMPLETED | 第三方和主审确认代码时序；权限绕过和实际副作用链尚未证明，实施前补最小生命周期回归 |

通用 fallback 目前没有完整控制语义比较、binding 没有安全字段，均有代码依据；但 OpenClaw 尚无原生权限映射，也未证明上游会话缓存旧权限。因此它们是新增权限前的检查项，不是立即全面改库的理由。

前轮构建与相关 91 项测试通过。本轮未重跑该套测试，新增证据仅包括上述隔离复现和源码审查，不能写成跨版本验收。

## 4. A 线：最小兼容修复，独立交付

### A0：先固定失败用例与旧契约

- 为 F1～F7 补最小行为测试；明确已证明的结果与尚需集成验证的影响。复用现有测试设施，不调用真实模型复现纯进程/状态问题。
- 从固定版本采集脱敏 CLI 输出、握手、订阅与 chat 终态 fixture，记录版本、来源和校验信息。保留现有 v3/v4、订阅/非订阅和 chat/session.message 分支。
- 在修改前确认真实旧版是否有请求 ID 或 ack 形状差异；替身生成的数据只能证明本方逻辑，不能当作旧版支持证据。

完成门槛：待修缺陷有失败回归；待验证事项不预先改造；不弱化旧断言。

### A1：补运行身份，稳定能力摘要

- 在现有能力接口上补 OpenClaw 实际入口、包版本、必要的包/入口身份；修复 `_runtime` 未被采集，不另建注册中心。
- CLI 和 Gateway 分开采集。Gateway 版本/协议来自已认证握手，不由本机 npm 版本代替；Node 版本独立记录。
- 当前调用所用的状态目录、配置选择和 Agent 身份进入必要上下文；不遍历并哈希所有插件、配置内容或整棵安装目录。将来某个权限依赖特定配置时，再加入对应摘要。
- 使用解析后的实际路径、包版本及入口文件身份识别升级；复用 stat/解析缓存，有变化时再刷新，避免每条消息运行版本命令或深度扫描。原地包更新、符号链接改指必须有测试。
- 语义 capabilityDigest 排除 observedAt/expiresAt 等仅观测元数据；真正影响控制的证据变化仍须使旧 preflight 失效。摘要变更采用明确修订，旧 preflight 一次性失效不能被静默放行。
- 保留 single-flight、超时、熔断与既有逐 Agent 缓存；只修复经测试确认会混用实例证据的键。没有 native controls 不代表可省略调用身份更新，但不为其新增无意义的权限等待。

完成门槛：无变化刷新可正常保存；真实身份/控制变化拒绝旧提交；CLI/Gateway 不同版本、版本未知、入口不可用均有准确状态。

### A2：CLI 与 Gateway 初始化的局部修复

- push/steer 共享必要的成功判定和输出解析，非零退出不得发成功回复。只有真实输出契约证明差异时才增加版本分支；不强制引入统一 planner。
- 复用 `agent --local --json` 连续会话入口。针对要求独占状态的路径，在 VOKO 本进程内按实际状态目录串行化自身调用，覆盖不同 Agent；等待有界、可取消。
- 跨进程竞争仍由 OpenClaw 的锁决定，不实现第二套持久或分布式锁。预检不能消除竞态，调用后的未知结果保护不变。
- 不通过解析 stderr 就把所有失败归为 not_delivered。需要可靠的执行前证据；否则保持 outcome_unknown，不自动重投。
- Gateway setup 仅在现有流程已明确选择并授权本地模式时补必要配置；remote/password/SecretRef 等首批可明确报告不支持该自动配置路径，不必全部新接入，也不能强制改 Token。
- 不停止主人已有 Gateway 来给 CLI 腾位置。先核实端口与本方子进程归属；修复中不扩大 `--force` 的使用范围。
- 本批不新增 Gateway CLI 代理路径，不切换 agent exec。它们只有确有必要且会话/认证/权限证据充分时才另立小项。

完成门槛：失败不误报成功；共享状态并发可控；已有 Gateway 占用时给出真实原因；既有配置和会话选择不被覆盖。

### A3：WS 契约与最小终态修复

- 继续按 features.methods/events 和协议协商选择现有路径。发行版本用于定位已知差异，不取代功能协商；默认不为每个发行版建完整适配器。
- 有合法挑战时间时按相应协议使用；已知旧契约的缺字段兼容单独测试。畸形挑战不靠回退本机时间掩盖。保留仍被接受的 v2 签名。
- 认证成功与 connect 请求、协商协议和 hello 结果关联；旧 ack 例外必须有固定版本证据，不能无条件接受任意 res.ok，也不能未经验证一刀切拒绝旧响应。
- 针对 F7 复用现有 Provider 事件与 turn 状态，区分已发送、已接受、已完成。订阅成功不是模型接受，push 返回不是终态；只有可信关联的结果才能完成对应 turn。
- 按已有超时/断线处理保留结果未知，不顺势重写所有 Provider 的取消、恢复、调度框架。影响共享 dispatcher 时必须增加相关同步/异步 Provider 回归。

完成门槛：发送后 turn 不提前完成；关联 final 正确结束；失败、重复 final、断线与超时不重复执行、不串会话；旧协议用例保留。

### A4：诊断和交付

- 在现有状态和“访客权限与安全”页面补准确的 CLI/Gateway 版本、调用兼容与证据状态，未知不伪装为已验证。
- 保留 additionalPrompt 及原配置；明确它只影响模型行为，不宣传 Shell/文件/网络强制边界，不新增提示词型权限开关。
- 更新 OpenClaw 指南和兼容矩阵；按受影响范围运行构建、针对性测试及项目要求的 CI。记录真实模型回复和 IM 投递是否实际验收。

A 线完成不依赖 B 线新增原生权限，不能宣传为“OpenClaw 全权限控制已完成”。

## 5. B 线：具体原生权限具备证据后，按项交付

B 线承接“访客权限与安全”的原目标，不取消该工作；先调查并交付控制证据清单，然后只实现确实可执行的控制。调查未找到可靠机制时，“不支持并说明原因”也是明确交付，不为了完成清单添加无效开关。

| 项目 | 进入实现的条件 | 最小实现与验收 |
| --- | --- | --- |
| Shell、文件、浏览器、网络、工具、MCP/插件、审批控制 | 具体版本/transport 的参数或协议确可约束该能力，已确定执行作用域 | 增加该项映射、预览、后端校验与无副作用 canary；不能由 loopback 证明权限 |
| 原生 Agent 配置写入 | 某控制确实要求持久配置且目标由 VOKO 管理，不能影响主人共享实例 | 复用 native policy adapter；必要配置摘要、备份和原生应用确认，失败不显示已生效 |
| fallback 权限等价 | 自动候选之间存在原生权限或已要求策略差异 | 先仅允许逐项确认的等价映射或禁用不兼容候选；不做通用权限偏序引擎；额外提示语按已有 transport 配置语义保留，不将其视为强制权限 |
| binding 扩字段 | 复现上游 session 缓存旧策略，或现有实例/transport/acceptsBinding 无法表达恢复差异 | 先复用既有恢复校验；确有必要才加最少字段和迁移，只标记受影响 binding，不一概阻断旧会话 |
| 在途策略变更/共享作用域治理 | 即将开放的权限收紧或配置变更会影响仍运行任务或共享实例 | 排队重规划；在途明确完成或可靠取消后才应用。无法确认即阻止受影响作用域继续自动执行，不假装已撤销；必要时增加最小恢复入口 |

每项原生控制上线前必须满足：UI、preflight、commit、实际执行使用同一能力与本轮策略；身份/相关配置变化使证据失效；未知版本不能继承未验证权限；降级不弱化用户要求；运行中策略不被偷换。这些是 B 线的硬门槛，不能以“后续优化”为由先开放开关。

首次原生权限接入前，补齐该控制实际需要的会话与在途保护；不预先要求所有控制共用一套完整状态机。补充提示语变化不等同于撤销正在运行的原生权限。

## 6. 验证矩阵与环境隔离

| 测试层 | 范围 | 证据标记 |
| --- | --- | --- |
| 日常契约回归 | 各条规则、错误分类、指纹、摘要、WS 事件、CLI 失败及会话隔离 | fixture/单元，不标真机 |
| 固定版本探测 | 三个版本锚点，至少覆盖每一种实际行为差异；CLI/Gateway 混合版本 | 按具体版本/平台/transport 记录成功、失败、未测 |
| 三平台快速层 | macOS、Ubuntu、Windows 各一套已就绪主版本；跨平台代码改动覆盖 Windows shim 和路径行为 | 缺主机/依赖则标未覆盖，不能声称三平台全过 |
| 发布前风险扩展 | 受影响旧版边界、最新版本、并发锁、未知/预发布与恢复路径 | 不要求所有维度笛卡尔乘积，但所有声称支持的差异须有证据 |
| 真实功能验收 | 专用测试 Agent 两轮、附件及 VOKO 消息投递 | 模型回复与 IM 回执分开；不替代权限 canary |
| 每项权限验收 | 允许操作成功、禁止操作拒绝、升级失效、降级不弱化及必要在途/会话测试 | 精确版本和控制证据，未通过不开控制 |

旧版安装在独立目录、配置、状态、工作区与端口，记录官方包完整性和对应 Node 环境；不替换当前全局 2026.9.2，不让旧版读取主人真实状态。旧包取不到或环境不满足时列缺口，不伪造支持。

权限 canary 只使用测试目录和受控本地端点，不读取真实秘密、不破坏数据、不向外部人员发消息。日志不保存完整 argv、配置、Token、访客原文或私密路径。CLI/WS 和 Pull 的结果不混称“已投递”；Owner、A2A、精确绑定与 E2EE 不为测试通过而跨越既有边界。

优先复用：`provider-capability.test.js`、`provider-security-policy.test.js`、`web-provider-security.test.js`、`provider-conversation-bindings.test.js`、`lite-openclaw-provider.test.js`、`lite-expanded-cli-providers.test.js`、`openclaw-chat-fallback.test.js`、`openclaw-attachment-lifetime.test.js`。

## 7. 执行顺序、回滚和完成标准

顺序：A0 → A1 → A2/A3 → A4；A2/A3 是独立提交边界，不自动委派并行 Agent。随后交付 B 线调查结论；每个成立的原生控制连同所需保护和测试独立交付。通用修改先复现影响，再做最小修复和其他 Provider 回归。

A 线不预定数据库结构迁移，也不修改投递顺序。确有 B 线字段需求时采用增量兼容迁移；不删除原权限/历史，不承诺任意降级旧 VOKO 可保留新安全保证。回滚须核实所需权限仍被执行，否则停止受影响自动路径。回滚 VOKO 不自动降级 OpenClaw 状态存储。

完成须提供：变更与测试记录、固定版本支持矩阵、未覆盖项、已开放控制及其证据、未支持控制原因、回滚限制。小批次提交仅包含必要实现、测试和文档；发布/部署另行授权。
