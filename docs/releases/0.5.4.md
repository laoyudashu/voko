# VOKO 0.5.4

状态：发布准备中，尚未发布 npm 或 GitHub Release。

## 主要变化

- 访客消息准入统一覆盖 Push、Pull 和历史恢复；私聊、群聊 @ 均遵守黑名单和下架状态，群聊 @ 不授予额外权限。
- 根据实际 Provider、传输、版本与操作系统映射可执行的原生权限及默认值，保留用户明确配置，不为能力不足的运行时虚构强制控制。
- MCP/CLI 保留明确发送失败和未知投递结果；重启后根据持久化状态恢复终态，丢失的精确错误码使用通用原因。未知结果不自动重投。
- 简化注册提示，将访客分享入口集中到 Agent 详情，提供二维码下载和显式链接访问模式选择。

## 兼容性与限制

- Node.js >=22.5.0。原生能力依赖实际运行时检测；三端验收不代表所有 Provider 版本或操作系统组合均支持同样的权限。
- AgentDID 目录对可搜索但不进黄页 Agent 的密钥访问修复独立部署，不包含在 npm 包内。黑名单和接收方真实访客准入继续生效。
- 历史 PEER_NOT_FOUND 持久化会话锁不会因本次升级自动解除。部署验证中 Linux ZeroClaw 的一条旧会话仍被 E2EE_V2_CONVERSATION_LOCKED 阻挡，接收侧加密失败回执的回传也待完善。没有清库、强行解锁或明文降级。
- 三端真实 CLI/MCP 消息已各验证执行完成及回复送达，包含原先失败的 Linux→macOS 路径；这不替代所有 Provider、附件及访客浏览器的验收。

## 验证

部署候选修复在 macOS、Ubuntu、Windows 定向各 99/99；安装后原生策略各 53/53；AgentDID 全量 353 通过、1 跳过。发布分支将重新运行完整门禁、浏览器、安全扫描与 GitHub CI。

此前三项旧测试仍假设注册强制传入 private、短链无需保存访问模式、首页存在旧访问按钮；发布准备已将测试更新为当前交互约定，并保留 owner token 与客户端目标 URL 拒绝断言。原生策略测试仅读取完整 NDJSON 行，避免并发写入期间解析半行。

## 升级与回退

正式发布后运行 `npm install -g @voko/lite@0.5.4`，或用 `voko update` 安装官方 registry 的稳定版本。升级前备份本地数据，升级后重新检测 Provider 能力。若需回退可安装 `@voko/lite@0.5.3`，但会失去本版本修复，且不会撤销已执行任务或回退上游 Agent 状态。

发布准备额外修正了 Web 群聊 `@所有人` 权限查询的 `channelId` 参数。浏览器回归按真实 owner cookie 验证实时消息，SENDACK 丢失明确验证 `DELIVERY_UNKNOWN`；本地会话测试使用与运行时一致的数据库锁等待。A2A 分享的真实浏览器测试迁入 Playwright 层，避免 Node CI 对开发机浏览器安装的隐式依赖。

最终本地发布门禁通过，Chromium 40/40，Gitleaks 与 CodeQL extended 通过。Windows 原生策略测试已创建独立的 Copilot loader fixture，不再依赖宿主预装 Copilot；本机 Windows 重验 53/53。远端门禁结果以最终提交的 Actions 为准。

权限页面将“权限对应的通信模式”单独放到下一行。跨平台 CI 修复收窄了强制退出的使用范围，离线同步测试在独立 Node 进程内关闭测试子进程序列化；Windows CIM 身份查询保持失败关闭，并将单次查询等待上限从 5 秒调整为 15 秒，以容纳负载下的冷启动。最终发布以包含这些修复的提交及其完整门禁为准。
