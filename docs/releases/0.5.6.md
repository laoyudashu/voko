# VOKO 0.5.6：网关认证、恢复与 Hermes 修复

状态：准备发布，尚未确认 npm 与 GitHub Release 可用。

## 发布范围

- 统一 Hermes、OpenClaw Gateway 启动与认证就绪判定，遵循所选运行时，显示启动失败原因。
- 修复 Hermes profile 认证、精确路由、配置更新和网关恢复边界；更新 YAML 时保留无关配置并创建备份。
- 请求提交后若 Hermes Provider 停止或被替换，迟到回复记为 `outcome_unknown`，不再误报完成，也不自动降级重发。
- Hermes 注册优先读取本地 profile 配置，避免反复启动原生 CLI 带来的延迟；本地目录不可识别时保留 CLI 发现路径。
- 恢复 WorkBuddy 运行时验证，完善 Provider 启动诊断及提交前后的结果分类。
- 用 Node.js 内置 crypto 替换废弃的 crypto-js，保留 IM AES-CBC/PKCS7 文本线格式；不是 E2EE 协议升级。
- 将间接依赖 Hono 的锁定版本更新为 4.13.7，修复依赖审计发现的问题。

## 升级与兼容性

Node.js 要求保持 `>=22.5.0`。本次只发布 `@voko/lite`，不升级独立 Chatroom、AgentDID 或 Hermes 本体，也不部署服务端数据库迁移。

发布确认后可执行 `npm install -g @voko/lite@0.5.6`，或运行 `voko update`。升级前备份本地数据，等待已提交请求结束，再按现有运行方式重启 Lite；安装新包不会让已运行进程自动加载新代码。结果未知时先核对原始任务和消息记录，不要重复派发。

profile 被发现不代表模型凭据、HTTP 认证或 IM 连接已经就绪。网关检查需要实际认证通过；模型成功回复也不等于访客已收到 IM 消息。参见 [Hermes 指南](../providers/hermes.md)。协作功能仍受 [0.5.5 服务端要求](0.5.5.md#服务端与兼容性)约束。

## 验证范围

发布准备前的定向验证：

- macOS 与 Ubuntu 各 208 项通过；Windows 206 项通过、2 项 POSIX 符号链接测试跳过。
- macOS 额外 Dispatcher/CLI Provider 回归 87 项通过。
- macOS 使用修复后的 Hermes HTTP Provider 完成一次真实模型请求，约 5.6 秒返回预期内容；没有将此测试视为外部 IM 投递验收。
- Windows 本地 profile 发现连续 100 次约 470 毫秒，与原生 CLI 的 profile 名称及默认选择一致；完整注册测试通过。

这些是定向证据，不能替代最终提交的完整发布门禁，也不代表所有 Hermes 版本、模型和工具权限组合都已实测。完整 PR/main CI、安全扫描、准备产物与发布记录将在发布后补充。

## 发布流程

按 [发布流程](../../RELEASING.md)与[发布清单](../../RELEASE_CHECKLIST.md)执行：版本 PR 通过必需检查后合并，等待 main 完整矩阵并运行 `release:preflight`；触发 **Publish npm**，版本 `0.5.6`、`prerelease=false`。审核准备产物后审批 `npm-production`，由 OIDC 发布并核对 npm tarball SHA-512、provenance、标签和 GitHub Release。

npm 上传成功但暂不可读时等待验证，不重复上传同一版本。
