# VOKO 0.5.3 发布说明

状态：发布准备，尚未发布。该文档随版本 PR 提交；合并、npm 发布和 GitHub Release 是后续步骤。源码版本为 0.5.3，正式发布前 `npm install -g @voko/lite` 仍安装 registry 的当前稳定版。

## 主要变化

- **OpenClaw 版本兼容**：读取旧 `agents.list` 与新 `agents.entries`；未知版本先检查 CLI 参数契约；Gateway 版本取自认证握手。同一状态目录的 CLI 调用排队，避免并发争用。仅当自身启动的 Gateway 明确要求迁移后重启时恢复一次，两次尝试共用 90 秒预算，启动错误提供脱敏诊断。包版本与文件身份使用同一已打开文件读取，避免升级替换期间的检查/读取竞争。
- **Codex 访客权限**：根据实际 CLI 参数和原生沙箱读写检查开放权限，而不是按版本号推断。运行入口变化后重新验证；首轮和恢复调用保持相同沙箱及审批语义。失败时显示阶段、退出码和脱敏摘要，不绕过沙箱。
- **通信与安全修复**：加强本地 Web 会话与事件流授权、MCP 输入检查和目录访问拒绝后的加密投递边界；修复离线同步断点、缺口与续传，以及终态回执恢复。保留执行证据，结果未知时不自动重投任务。
- **其他 Provider 修复**：改进 ACP 连接失败分类、WorkBuddy 启动诊断与 loopback 隔离、OpenHands 安全钩子失败处理、Windows Copilot 发现与进程归属判断、Aider 回复尾部过滤。
- **升级与发布**：统一使用官方 npm registry 发现和安装更新；本地页面显示可升级的确切版本。发布扫描覆盖实际 npm tarball，并拒绝路径别名及特殊文件等不安全输入。

## 兼容性与已知限制

兼容机制覆盖旧版、当前版和未知版本的能力判定，不代表所有发行版或所有宿主环境均已验收。

- OpenClaw 参数/握手锚点为 2026.6.1、2026.7.1-2、2026.9.2。macOS 2026.9.2 和 Windows 2026.7.1-2 的 CLI/WS 模型首轮与会话恢复通过；Ubuntu 测试入口缺少 DeepSeek 凭据，模型执行被阻塞。OpenClaw 原生权限尚未绑定为 VOKO 可验证的逐回合控制，因此没有新增权限开关。
- Codex macOS 0.153.4 的沙箱、模型首轮及会话恢复通过；Ubuntu 0.148.0 被 bwrap 初始化权限拒绝，Windows 0.148.0 的 workspace-write 检查仍拒绝工作区写入，两个环境的访客 Provider 保持提交前阻止。旧式平台沙箱子命令仅有模拟契约覆盖。
- 上述窄范围 Provider 真机验证不包含附件、访客 Web、E2EE 或 IM 投递验收，不能用模型回复代替完整投递证明。

详细证据与操作说明：[OpenClaw 兼容性](../providers/openclaw-compatibility.md)、[Codex 兼容性](../providers/codex-compatibility.md)。

## 升级与回退

正式发布并核对 npm 版本后，可运行 `npm install -g @voko/lite@0.5.3`，或使用 `voko update` 安装 registry 当前稳定版本。需要 Node.js >=22.5.0。

升级后在“访客安全与权限”重新检测，查看当前宿主环境的实际结果。该版本不会替用户升级 Codex/OpenClaw，也不自动把 OpenClaw 原生配置改成统一权限模板。OpenClaw 已保存的补充提示语无需迁移；升级前未提交的 preflight 应重新获取。

若需回退 VOKO，可安装 `@voko/lite@0.5.2`；这不会回退上游 Agent 状态或撤销已执行任务，也会失去本版本的安全与可靠性修复。

## 发布准备验证

2026-09-05 本地 macOS / Node 26.7.0：完整 `release:gate` 通过，1642 项测试中 1640 通过、2 项平台条件跳过，类型检查、i18n、覆盖率和生产依赖审计通过；Gitleaks 与 CodeQL extended 门禁通过。

Chromium 39 项浏览器测试通过，测试基础设施 6 项回归通过。发布检查还修复了浏览器测试目录请求误连公网的问题：仅在测试子进程内注入本地 API 地址，不改写构建配置、不关闭 E2EE；模拟目录明确声明旧式测试收件人不支持 E2EE，并以真实浏览器验证目录 401 时 IM 发送计数不增加。

CodeQL 的 manifest 检查/读取竞争已由失败回归确认并修复；挑战时间戳拒绝条件为误报，按规则、文件与精确指纹记录理由，未删除安全校验。GitHub PR 的 Node 22 三系统、Rust E2EE 和 CodeQL 结果以对应 Actions 为准；此处本地通过不代替远端门禁或 main 合并后的完整矩阵。

## 发布流程

版本 PR 通过后合并 main，并等待 main 完整矩阵。按 [发布清单](../../RELEASE_CHECKLIST.md) 从 main 运行 **Publish npm**，版本填 `0.5.3`，稳定版设置 `prerelease=false`。审批准备好的不可变 tarball 后由 OIDC 发布 npm，成功验证后工作流创建同一 SHA 的 `v0.5.3` 和 GitHub Release。

工作流自动生成 GitHub Release 正文；发布后将本说明的主要变化、限制及验证链接整理到正文，并将此页状态更新为已发布。不要预先创建同名 Release 或 tag，工作流会拒绝覆盖。
