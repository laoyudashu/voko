# 下一版发布准备：协作任务与云空间

状态：文档准备，尚未发布。当前包版本仍为 0.5.4；本页不代表这些改动已进入 npm，也不为下一版预先指定版本号。确定版本后，将本页整理为 `docs/releases/X.Y.Z.md`，同步包版本、锁文件、README 和 Changelog。

## 发布范围

- Web UI 将群工作区整合为协作聊天、任务、看板、资产、成员与设置。
- 任务支持明确派单、隔离执行、输入资产下载、输出上传及执行回执，保留人工验收。
- 未知执行保留本地恢复信息和文件，不自动重跑；符合条件的迟到回复关联原执行。
- 云空间配置根据服务端目录展示七牛、COS、S3、R2 的专属字段。
- DeepSeek Harness HTTP 适配与访客权限预设修复，详见[专属指南](../providers/deepseek-harness.md)。其版本、契约与实际权限范围不应推广到所有 Provider。
- 上传 Agent logo 后访客二维码仍可工作。
- npm 发布后的可见性验证改为独立等待任务，避免已上传版本被重复发布。

使用入口、术语与排障见[协作指南](../collaboration.md)；完整变更见 [Changelog](../../CHANGELOG.md)。

## 服务端与兼容性

Node.js 要求保持 `>=22.5.0`。Lite npm 包不包含 Chatroom 后端、MySQL 迁移或独立 AgentDID 服务。只发布客户端不等于协作服务端已升级。

部署者应先确认 Chatroom 的协作任务 API 和存储加密配置已就绪。多厂商改动在独立 Chatroom 仓库，需要备份数据库，在已有 010 迁移的基础上执行一次 `011_storage_providers.sql`，再部署相应服务端与前端，最后更新 Lite。011 保留旧七牛配置并增加 R2 账号范围；不可重复执行。仅该多厂商改动不要求部署独立 voko-server。

旧服务端未返回厂商目录时，客户端保留七牛表单。新服务端未上线的云空间厂商不会仅凭客户端升级就可用。已有资产禁止直接切换存储位置；不包含跨云迁移。

协作消息、元数据和加密后的客户凭据仍涉及 VOKO 服务端；资产内容由客户云空间保存。本地执行仍有临时文件，且 Provider 可能处理明文，不将这一路径描述为私聊端到端加密或完全本地运行。

## GitHub 发布步骤

按 [发布流程](../../RELEASING.md)及[发布清单](../../RELEASE_CHECKLIST.md)执行：从候选代码建立版本 PR，经 GitHub 必需检查合并到 main，等待 main 完整检查，通过发布预检，再触发受保护的 **Publish npm**。稳定版设置 `prerelease=false`，审核准备产物后审批 `npm-production`。

由工作流通过 OIDC 发布，校验 npm tarball 的 SHA-512 与来源后创建对应标签和 GitHub Release。npm 上传成功但暂不可读时等待或重试失败的验证任务，不重复上传。Gitee 同步不等于 GitHub main 已通过检查或 npm 已发布。

升级前备份本地数据并完成服务端验证。客户端回退不会回退 MySQL、撤销已派发的工作或删除云端资产；对结果待确认的执行不要因回退而重新派单。
