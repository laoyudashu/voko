# 访客私聊端到端加密

[文档索引](README.md) · [E2EE 安全模型](e2ee-security-model.md) · [隐私说明](../PRIVACY.md)

VOKO 对具备条件的浏览器访客与本地 Agent 私聊默认使用 `voko.e2ee/2`。访客和 Agent 不需要手动建链，也不需要维护群组、epoch、KeyPackage 或平台原生加密组件。

## 适用范围

当前 E2EE 只覆盖：

- 浏览器访客与本地 Agent 的一对一私聊；
- 私聊文字；
- 私聊图片和文件（客户端与服务端附件能力均可用时）。

群聊、A2A Gateway、External REST/Webhook Gateway、MCP、CLI、邮件和支付继续使用各自的 TLS 通信与访问控制，不属于该 E2EE 声明。

## 工作方式

每个浏览器设备与每个 Agent 各自维护独立的 X25519 加密密钥和 Ed25519 签名密钥。公钥登记在 AgentDID，私钥只保存在端点。发送每条消息时，发送端读取接收端公钥，使用 HPKE 为该消息生成独立密文并签名；中继服务只转发密文和必要路由元数据。

Lite 在本机验签、解密和校验路由后，把明文写入普通本地消息记录，并通过现有安全审核和 Provider 路由执行。Provider 回复在 Lite 本机重新加密后返回浏览器。

附件使用独立的随机 AES-256-GCM 内容密钥分块加密。内容密钥、文件摘要和清单放在 HPKE 密文内，OSS 只保存私有密文对象。

## 用户体验

- 支持 E2EE 时自动使用加密通道，普通用户无需点击或等待单独建链。
- 正式界面默认不显示调试钥匙；调试构建可显示当前消息是否使用 E2EE。
- 浏览器刷新或 Lite 重启不会更换已有设备私钥。
- 每条消息独立加密，单条密文损坏不会推进或破坏后续消息状态。
- 本地保存的已解密消息按普通消息显示，历史页面无需逐条重新执行 Provider。

如果端点私钥确实丢失，旧密文无法恢复。系统会为后续消息登记新的设备密钥；不会用新密钥伪装成已恢复旧密文。本轮不兼容、导入或迁移实验版 `voko.e2ee/1` 数据。

## 信任边界

AgentDID、WuKongIM 和 OSS 只处理密文，但仍可见参与者、路由、时间、在线状态和密文大小等元数据。浏览器、Lite、本地 VOKO 数据库、本地 Web UI 和被选择的 Provider 是明文端点；若 Provider 使用云模型，内容也进入该 Provider 的服务边界。

日志只允许记录阶段、错误码和短摘要，不得记录明文、私钥、完整密文、附件内容密钥或原生 Provider Session。
