# 访客私聊端到端加密

[文档索引](README.md) · [E2EE 安全模型](e2ee-security-model.md) · [隐私说明](../PRIVACY.md)

VOKO 当前为浏览器访客与本地 Agent 的一对一私聊提供可选 E2EE。聊天初始仍为普通 TLS 通信；只有用户点击聊天标题栏的钥匙并完成建链后，新消息才进入 `voko.e2ee/1` 加密通道。

## 钥匙状态

| 状态 | 含义 | 用户操作 |
| --- | --- | --- |
| 灰色钥匙 | 当前环境具备条件，但会话仍是普通通信 | 点击后开始建立 E2EE |
| 黄色闪动 | 正在建立加密通道 | 等待；输入框暂时不可用 |
| 绿色钥匙 | 后续新消息使用 E2EE | 正常发送 |
| 红色钥匙 | 已加密会话的密钥或状态失效，禁止降级 | 点击并确认建立新的加密会话 |
| 不显示钥匙 | 浏览器、Agent 或服务端当前不具备 E2EE 条件 | 继续使用普通 TLS 通信 |

建立期间输入框显示“加密通道建立中，请稍后…”。首次建立失败时，会话回到普通模式，用户可以清除输入框提示并继续普通通信；已经进入加密状态的会话发生密钥丢失或解密失败时不会静默降级，必须明确重建。

建立通常需要数秒，取决于浏览器 WASM 初始化、一次性 KeyPackage 获取、Lite 轮询和网络往返。不同浏览器和微信内置浏览器的耗时可能不同。请勿反复点击或同时在多个页面为同一访客会话建链。

## 覆盖范围

当前生产 E2EE 覆盖：

- 浏览器访客与本地 Agent 的一对一私聊；
- 该私聊中的文字，以及客户端和 Provider 均支持时的图片/文件；
- Windows、Ubuntu 和 macOS Lite；支持 WebCrypto、IndexedDB、WebAssembly 和单写者协调能力的现代浏览器，包括已验证的 Android 微信内置浏览器。

当前不属于该 E2EE 声明：

- 群聊；
- A2A Gateway；
- External REST/Webhook Gateway；
- MCP、CLI 与本地 Web UI 的控制连接；
- 邮件、支付和其他旁路通知。

这些场景继续使用其既有 TLS 通信和访问控制。它们不会显示 E2EE 标识，也不能被描述为端到端加密。

## 数据在哪里解密

E2EE 保护浏览器与本地 Lite 之间的传输和中继存储：AgentDID、WuKongIM 和 OSS 只处理密文。Lite 在本机解密后，按普通可信入站流程执行安全审核、写入本地消息记录、显示在本地 Web UI，并把明文交给目标 Provider；Provider 回复在 Lite 本机加密后返回浏览器。

因此，本地 Lite、VOKO 本地数据库、本地 Web UI 和被选择的 Provider 都是明文端点。若 Provider 本身使用云模型，内容也会离开本机进入该 Provider 的服务边界。E2EE 不等于“任何地方都不出现明文”。

## 历史消息和重建

- 启用前的历史消息保持普通通信记录，不会被追溯加密。
- 当前端仍有本地明文缓存的历史消息可以继续显示。
- 若只剩旧密文而旧密钥丢失，该内容显示为无法解密。
- 重建会创建新的加密安全边界，不会用新密钥伪装成恢复旧会话。
- 同一浏览器账号的多个标签页通过单写者锁共享状态；不同浏览器、手机或浏览器资料目录是不同设备，不能假设共享私钥。

## 故障排查

1. **没有钥匙**：确认使用 HTTPS、浏览器支持 WebCrypto/IndexedDB/WebAssembly，目标 Agent 已发布且 Lite E2EE 正常在线。
2. **`KEY_PACKAGE_UNAVAILABLE`**：等待 Lite 补充一次性 KeyPackage 后重试；持续失败时检查 AgentDID Directory 与 Lite 日志。
3. **一直正在建立**：关闭同一会话的其他建链页面，刷新一次并重试；检查 Lite 是否在线及 Directory 是否可达。
4. **红色钥匙或解密失败**：不要继续明文发送；点击钥匙并确认重建。
5. **普通消息能回复但加密消息不能**：检查 Lite 是否已领取 `contentType=13`、Provider 是否完成回复、回复密文是否使用同一 group/epoch/conversation scope。

日志和错误报告只能记录脱敏错误码、阶段和短摘要，不得包含明文、密钥、完整密文、KeyPackage 私有材料或 Provider Session。
