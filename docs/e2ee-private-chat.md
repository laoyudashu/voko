# 私聊统一端到端加密

[文档索引](README.md) · [E2EE 安全模型](e2ee-security-model.md) · [隐私说明](../PRIVACY.md)

VOKO 将 `voko.e2ee/2` 作为私聊 IM 的统一底层能力。具备兼容设备密钥时，无论消息来自 Chatroom、Web UI、CLI、MCP、Provider 回复或系统通知，都由同一个安全出站路由器完成加密；调用方不需要传入新的必填参数。

## 适用范围

当前 E2EE 覆盖：

- 浏览器访客与本地 Agent 的一对一私聊，包含同一访客的多个有效设备；
- 已注册 VOKO Agent 之间的一对一 IM 私聊；
- Web UI、CLI、MCP 主动发送，Provider 回复，以及支付、审核等系统私聊通知；
- 私聊文字、图片和文件。

群聊、A2A Gateway、External REST/Webhook Gateway 和邮件继续使用各自的 TLS 通信与访问控制，不属于该 E2EE 声明。MCP 和 CLI 本身是本机控制入口，不是 E2EE 传输协议；但它们发出的私聊 IM 消息会进入统一 E2EE 决策器。

## 工作方式

每个浏览器设备与每个 Agent 各自维护独立的 X25519 加密密钥和 Ed25519 签名密钥。公钥登记在 AgentDID，私钥只保存在端点。发送每条业务消息时，发送端读取接收方全部有效设备公钥，为每台设备生成独立 HPKE 密文并签名；业务消息只执行和展示一次，每台设备只接收属于自己的信封。

Lite 在本机验签、解密和校验路由后，把明文写入普通本地消息记录，并通过现有安全审核和 Provider 路由执行。Provider 回复在 Lite 本机重新加密后返回浏览器。

附件使用独立的随机 AES-256-GCM 内容密钥分块加密。内容密钥、文件摘要和清单放在 HPKE 密文内，OSS 只保存私有密文对象。

## 用户体验

- 对方明确支持 E2EE 时自动使用加密通道，普通用户无需点击或等待单独建链。
- 从未加密且服务端明确确认不支持时使用明文；能力暂时未知时本次可使用明文并在短暂退避后重新探测。
- 已成功使用过 E2EE 的 Conversation 永不静默降级；密钥撤销、身份变化或 Directory 不可确认时会锁定发送。
- 正式界面默认不显示调试钥匙；调试构建可显示当前消息是否使用 E2EE。
- 浏览器刷新或 Lite 重启不会更换已有设备私钥。
- 每条消息独立加密，单条密文损坏不会推进或破坏后续消息状态。
- 本地保存的已解密消息按普通消息显示，历史页面无需逐条重新执行 Provider。

如果端点私钥确实丢失，旧密文无法恢复。系统会为后续消息登记新的设备密钥；不会用新密钥伪装成已恢复旧密文。新加入设备不自动补发历史密文。本轮不兼容、导入或迁移实验版 `voko.e2ee/1` 数据。

## 接口返回

`send_message` 和 `upload_and_send_file` 保持原参数兼容，并在响应中增加 `securityMode`、`securityReason`、`encryptedDeviceCount` 和 `deliveryState`。群聊固定绕过私聊决策器；私聊的图片、文件和随附文字必须使用同一次设备快照，不能一部分加密、一部分明文。

## 信任边界

AgentDID、WuKongIM 和 OSS 只处理密文，但仍可见参与者、路由、时间、在线状态和密文大小等元数据。浏览器、Lite、本地 VOKO 数据库、本地 Web UI 和被选择的 Provider 是明文端点；若 Provider 使用云模型，内容也进入该 Provider 的服务边界。

日志只允许记录阶段、错误码和短摘要，不得记录明文、私钥、完整密文、附件内容密钥或原生 Provider Session。
