# Provider 访客准入 P0 实施验收

日期：2026-09-07。用户已明确授权“实施”。代码与定向回归完成，尚未提交、推送或部署。

## 结果

修复的是 VOKO 控制的输入路径：同一 Agent 已拒绝的访客消息不能从 Push、Pull、恢复历史或 E2EE 直接调度绕回 Provider。群聊 @ 只决定触发目标，不构成越过黑名单、下架、成员资格和审核的授权。

| 范围 | 实现与验证 |
|---|---|
| 准入决定 | `message-admission.ts` 持久化每 Agent/消息的 pending、allowed、denied；缺记录不作为许可，终态拒绝不自动重审放行 |
| 接收与审核 | `messenger.ts` 原文与 pending 原子保存；Pull-only 同样审核；模型等待有超时；中断记录仅持运行实例锁时恢复为拒绝 |
| 群聊 | 结构化 UID 定位目标；@all 要求群主/管理员，普通成员混用 all+UID 整条触发无效；首次与精确路由均检查成员资格；A 拒绝不改写 B 共用的群原文 |
| 群历史 | 新的未 @ 消息不阻塞触发游标；运行实例中按有界候选窗口审核，完成才用于上下文；短 CLI 不创建无法接续的审核任务 |
| 读取与恢复 | MCP/CLI 历史、访客近期消息、会话摘要、人工介入原文和两套私聊恢复均受共同规则约束；群返回检查成员；异步等待后再次核对全部候选 |
| Pull 游标 | 单频道、阻塞和全量路径一致；pending 不越过；跨频道总 limit 不先推进未返回消息的游标；后处理不产生稀疏数组 |
| 最终提交 | 当前消息、合并来源及已引用历史重新检查；CLI/ACP/HTTP/WS 内部等待后的实际提交点保留准入回调；加密批次按所有本地消息 ID 检查 |
| 主人原文 | 有效主人 Web session 可查看原文；实例 token 不授予原文权限；消息 WS 限主人，Console 初始与后续 snapshot 对实例 token 隐藏原始事件/审核记录 |
| 迁移 | schema v10；升级备份、重复迁移与写入失败回滚已验证；新消息入库标记不等于获准，旧记录保持未知；本地 Agent 新发群消息不会误作旧记录 |

## 独立审查与设计收敛

独立 Agent 多轮复核发现的实际问题均已闭合；最后确认暂无未关闭的明确阻塞项，未发现需要扩充架构的理由。保留一张小型准入表和现有路由/缓存/队列；未引入 policy version、权限 DSL、通用 Broker、新持久队列、自动补发或全群后台审核。详见 [独立审查记录](independent-admission-design-review.md)。

- 尚未进行真实 Provider/设备的端到端送达测试；本轮不声称各 Provider 的操作系统、工具、文件、网络权限已安全隔离。
