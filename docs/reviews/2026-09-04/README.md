最重要的对抗修正：

- 等待coalescer不代表等待Provider。生产flush回调返回void，必须看Dispatcher真实队列和A2A延迟定时器。
- A2A序号唯一索引只保证去重，不保证前序已执行。恢复方案本身也需要验证，不能为可用性降低顺序与签名约束。
- 正则Worker方案会牵动同步消息/事务接口；本轮拒绝默认上升为广泛异步重构。长度检查只能缓解超长输入，不修复501字节反例。
- 普通logout确实删当前Cookie；旧会话问题的成立路径是另一独立会话。全删session又会误伤激活前创建的新主人Cookie。

## 批准后的自动推进方式

批准对象是 `voko-lite-review-2026-09-04-v1` 的综合计划。批准后当前任务可按依赖连续完成：隔离基线 → 最小失败回归 → 小范围修复 → 定向验证 → 独立diff复核 → 汇总门禁 → 本地交付，并逐项更新执行台账。

当前没有创建定时任务或后台优化器，执行台账的 `approval.approved=false`。批准计划也不包含推送、合并、发布、生产部署、历史数据回放/清理或跨仓库修改。超范围的设计只暂停相关事项，其他独立事项可继续。

本v1完成不表示全部已知风险归零：R08完整修复、R14性能改造、R13背压与可能需要新设计的R19仍需保留明确状态；缺失的Node22/24、三系统和真实Provider验证不能标通过。
